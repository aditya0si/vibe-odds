# Court Evidence frontend design

Date: 2026-10-13. Status: design for review; implementation is not authorized by this document.

## Intent and boundaries

Court Evidence is a browser-readable evidence workspace for NBA and ATP tennis: what the model actually returned, when its inputs were observed, how historical evaluation was conducted, and what remains unproven. It is not a betting terminal. Rename visible page titles, brand, and adapter presentation titles only. Preserve vibe-odds repository identity, artifact paths, hashes, model IDs, API paths, coefficients, preregistration, and operational scripts.

Deliver two sequential milestones: a complete NBA frontend first, then tennis with its own adapter and actual ASGI integration tests. Both remain static HTML/CSS/JavaScript served by existing FastAPI apps. No framework migration, cross-origin aggregator, account system, paid feed, training, scheduled job, or backend prediction generation is included. Browser traffic is GET only; remove tracking, settling, learning, rollback, and promotional sharing controls. A GET can still cause provider cache/verdict-log writes internally: read-only browser operations do not imply a side-effect-free server. Integration tests must redirect those writers.

## Source-grounded baseline

Inspected HEAD: `328b977c33860d65705a0db4262224a0d5c4a096`, clean before documentation. `core/api.py:42-63` mounts each frontend directory at `/static` and injects `window.__ADAPTER__` via `core.site.inject_adapter` into `/`. NBA uses `sports/nba/site/index.html`, `sports/nba/server.py` (8010); tennis uses `frontend/index.html`, `backend/api/server.py` (8000 by deployment convention, not an in-file launcher). Do not assume either service is running.

The current NBA page collects eight endpoints at boot and converts errors to objects, then often renders missing values as empty/default zero. Its tier renderer reads `pass`, while evidence uses `passes`. Replace these behaviours, not the evidence. Tennis currently includes Value/post filters and a Run learner button; these do not belong in Court Evidence.

Both manifest inventories were read and byte-checked during planning: 41 tennis entries and 25 NBA entries match. The NBA live log is absent on this checkout. Absence is not permission to fabricate predictions. No live HTTP probe or test execution was performed for this documentation-only task.

## Approach and alternatives

Recommended: separate sport-local ES modules and CSS, preserving both serving roots and existing Python injection. Shared visual conventions and transport signatures are specified here, but files remain local so no shared static mount or backend route change is needed. Small duplication is preferable to coupling incompatible payloads.

Rejected initially: a bundled single-page application (new toolchain and deployment complexity without evidence benefit); one generic adapter that treats both boards identically (would obscure NBA pre-tip provenance and tennis mock fallback). Revisit packaging only after both milestones pass.

## Visual system and information architecture

Use a restrained evidence-notebook identity: warm off-white canvas `#F6F5F0`, white panels, ink `#17212B`, secondary text `#475569`, borders `#CBD5E1`, evidence blue `#1D4ED8`, caution amber `#92400E`, invalid red `#991B1B`. System UI typography, 16px body, 1.5 line-height, tabular numeric values; 4/8/12/16/24/32 spacing, 8px panel radius. No gradients, pulsing live markers, gambling-green confidence badges, trophy copy, or decorative probability gauges. Test contrast rather than assuming the palette guarantees it.

At 1280px: header and sport identity, accessible horizontal navigation, 1200px content width, main evidence area plus a 320px provenance rail. At 768px the rail stacks below; at 390px all primary content is single-column, charts and tables retain readable labels. Avoid page-wide horizontal scrolling. Dense tables get labeled scroll containers and a compact card equivalent for prediction rows.

NBA navigation retains `Matches`, `Teams`, `Model`, `Experiments`, `Methodology`. Matches defaults to all actual logged predictions, with Upcoming, Awaiting settlement, and Settled filters. Never label the unfiltered board Tonight. A valid past tipoff without settlement is Awaiting settlement, not a loss. Show game ID and home/away orientation where names are unavailable. Detail is inline expandable content, not an inaccessible modal. Historical reconstruction is a separate explicit game-ID lookup with a permanent historical badge.

Model: formula source, features/coefficient table, fit/tune/test windows, Brier and sample sizes, tier verdicts and paired intervals. Experiments: structured availability, calibration, ablation panels plus optional raw JSON disclosures. Methodology: scope, as-of discipline, artifact inventory and limitations. Teams: names, wins and as-ingested row counts; suppress win-rate/home-win-rate headline because their current denominators include scheduled rows. Never relabel these as completed-game rates.

Tennis retains Matches, Players, Model, Experiments, Methodology. Group choices are US Open/best-of-5 and ATP Tour/best-of-3. Surface selection belongs to player ratings, not match prediction: `_build_card` and `/api/predict` currently hardcode hard. Explain this limitation. Do not add a fictitious surface control. Display model probability and market reference as different series, with full versus market-free probability explicitly named. Remove Value/post/edge sizing as primary UX; optional historical policy data lives in evidence disclosures labeled retrospective paper simulation, not profit or market advantage.

## Exact existing adapter and API contracts

### Injection

`NbaAdapter.config`: `{title, sport:'nba', tabs:['Matches','Teams','Model','Experiments','Methodology'], api:{site_meta,board,predict,model,experiments,teams,reliability,sim,stats,live_log}}`; each API value is `/api/<key>`, except live_log=`/api/live/log`. `TennisAdapter.config`: `{title,sport:'tennis',surfaces:['hard','clay','grass'],groups:['usopen','tennis'],api:{health,board,players,model,stats}}`. Tennis predict/reliability/player-detail routes exist but are NOT injected today. Extend the tennis API dictionary explicitly for the new UI; do not pretend those keys already exist. Validate sport, supported tabs/groups, and same-origin `/api/` routes before fetching; absent/invalid injection produces Configuration unavailable, not a silently selected sport.

### NBA contracts (`sports/nba/server.py`, `evidence.py`, `live_log.py`)

- GET `/api/board` -> `{board:Array,n:number}`. Each row: `type:'predict',game_id:string,tipoff_ts:ISO,logged_at:ISO,prob_home:number,pick:'home'|'away',source:string`; optional `settled:{home_score,away_score,settled_at}`, optional `correct:boolean`. It is latest prediction plus latest settlement per game across ALL logged rows, sorted by tipoff. No names, team IDs, odds, or fetched/source-feed timestamp. Validate finite probability in [0,1], pick consistent with >=0.5, and timezone-bearing logged_at strictly before tipoff. Never trust backend admission alone: logger does not enforce probability range. Invalid rows are quarantined with visible count/reason, not normalized into plausible predictions.
- GET `/api/live/log` -> `{n_events,events}`; append-only predict and settle events. Optional audit disclosure only; do not treat settlements as prediction cards or assert board count equals event count.
- GET `/api/predict?game_id=<encoded ID>` -> either `{error,game_id}` with HTTP 200 or `{game_id,date,home_team_id,away_team_id,result_home_win:number|null,prob_home,pick,formula:'formula_v1.json',note}`. The latter is re-derived from v1 features and published coefficients, NOT a timestamped prospective record. Verify returned ID equals requested ID. Never put it in the live board or imply A7. `date` is game date, not prediction generation/freshness.
- GET `/api/site_meta` -> `{sport,tabs,artifacts:[{key,file,bytes,generated_by?}],scope,formula}`. Bytes and generated_by are not hashes or source timestamps.
- GET `/api/model` -> `{formula,tiers,pooled_all_test,pooled_with_close,pooled_with_open,n_test_games,notes,by_season,paired_vs_close,tuning_paired}`. Formula contains features, coef_raw, intercept_raw, n_train, train_end, tuned_on, test_seasons. Tier verdict uses `passes`, not `pass`. Missing verdict displays Unknown, never inferred success.
- GET `/api/experiments` -> `{availability,calibration,ablation}`; GET `/api/sim` -> frozen walk-forward artifact. Preserve each arm identifier and cohort, do not pool unlike samples.
- GET `/api/teams?limit=30` -> `{home_win_rate,n_games,teams:[{team_id,team,wins,games,win_rate}]}`. Counts include unscored scheduled regular-season rows; omit rates from summary as above.
- GET `/api/reliability?n_bins=10` -> `{n,bins:[{lo,hi,n,mean_p:number|null,rate:number|null}],ece,note}`; empty bins remain gaps, not zero-rate observations. Historical re-derived reliability, not live calibration.
- GET `/api/stats` -> `{db_counts,seasons:[{season,n}],artifacts}` with games/games_completed/games_scheduled split. Seasons are raw counts; do not infer completed counts per season.

A5 evidence is the v1 historical formula view. `tools/season_ops.py:17-23` explains A7 needs same-game inactivity inputs available only post-game in the free pipeline and has no live prediction subcommand. A sealed A7 prospective claim read with live-captured market prices is not a published pre-tip prediction log. Explicit copy: “Historical A5 evaluation does not establish prospective A7 prediction performance.” Model source on log cards is whatever validated `source` actually reports; never overwrite it with A7 branding.

### Tennis contracts (`backend/api/server.py`)

- GET `/api/health` -> `{ok,has_key,auth,provider,quota,groups}`. `has_key` is credential availability, not proof of live data. Provider last status is process-global, not an event-level attestation.
- GET `/api/board?group=usopen|tennis&market=h2h` -> `{group,feed,cache_age_s:number|null,matches:Array,summary:{n,value,disagree}}`. Card base: `{id,label,commence_time,n_books}`; error card adds `error,outcomes:Array`. Valid card adds `pick,conf,model_prob_a,badge,fair_source,warning,unknown_players,outcomes:Object,signals,weights_used,reasons,policy,policy_bandit,status,cold_start,flags`. Outcome map values: `{model_prob,model_prob_free,fair_prob,best_odds,best_book,edge,kelly_half,field_median,n_quotes}`. Status: `{started,thin,hours_old,bettable}`. Cold-start: `{guarded,players}`. Flags: `{disagree,gap,value,edge_raw,big_gap}`. Suppress promotional policy/value presentation regardless of these legacy flags. Validate exactly two outcomes, pick membership, finite probabilities, IDs, and meaningful time; do not infer model_prob_a orientation from away/home label, since outcomes are sorted alphabetically.
- GET `/api/predict?event_id=<ID>&group=<group>&market=h2h` -> `{event:{id,label,commence_time},verdict,market,fair_source,warning,unknown_players,feed,policy,tweet}` or `{error,...}`. Unlike board, verdict holds model fields and market is an outcome map without fair_prob. Critically an unknown event ID falls back to the first event: reject mismatched returned `event.id`. Do not render tweet or policy recommendation. Prefer board cards for primary detail to avoid another provider call.
- GET `/api/players?q=<query>&n=50&surface=hard|clay|grass` -> `{surface,players}`; GET `/api/players/<encoded name>?vs=<encoded name>` -> analytics player detail. Renderer reads only validated fields required by its view; preserve unavailable values. Player rows (`analytics.py:43-68`) contain `name,matches,overall,hard,clay,grass,blended,cold_start`. Detail (`78-137`) is either `{name,unknown:true,note}` or `{name,unknown:false,matches,overall,surfaces:{hard|clay|grass:{rating,n}},cold_start,form_last10:{n,win_rate},surface_splits:{surface:{n,wins,win_rate}},recent:[{date,surface,round,opponent,result}],form_trend:[{date,win_rate_10}],h2h_vs?}`. Detail performs canonical/substring fallback; display the returned canonical name rather than assuming exact query identity. Dates in recent/trend are integer YYYYMMDD, not ISO timestamps.
- GET `/api/model` -> `{sim,calibration_validation,column_tournament,ablation,gbm_freeze}`. sim contains n, arms, per_surface, confidence, paired_mean, gbm_vs_adaptive, gbm_vs_frozen, betting, policies, line_note, use_market. Calibration has n_fit,n_test,methods,verdict; tournament has sets,folds,improvement_vs_A,B_folds,verdict. Missing disk artifacts may become null or nested error objects.
- GET `/api/reliability?n_bins=10` and `/api/stats` remain separate: stats=`{stats,calibration,tuning,provider,quota}`, not NBA stats. Tennis reliability (`analytics.py:150-169`) is `{n,bins:[{p_mean,frac_pos,n}],ece_oof,note}` with equal-count bins, not NBA fixed-width bins; bind a dedicated renderer and do not invent lo/hi boundaries.

No ODDS_API_KEY forces mock events. Quota/error fallback may also produce mock; fetch_group can swallow provider exceptions. The group-level last mode and minimum cache age across group keys cannot prove every event is fresh or even homogeneous. This is a known backend limitation, not a problem solved by a green “Live” label.

## Proposed frontend interfaces and state model

Sport-local `transport.js`: `createReadClient({fetchImpl,now,timeoutMs:10000})` returns `getJson(path,{signal}={}) -> Promise<{kind:'ok',payload,fetchedAt}|{kind:'http'|'offline'|'timeout'|'invalid',message,fetchedAt:null}>`. It enforces same-origin relative API paths and GET, checks status/content/JSON, and never retries automatically. Sport adapters do payload validation and classify HTTP-200 error bodies. `request-state.js`: `createRequestSlot()` exposes `begin()->{generation,signal}`, `isCurrent(generation)`, `cancel()`; superseded response or error may not change current data, spinner, timestamp, or selection.

`nba-contract.js`: `parseBoard(payload,{fetchedAt,now}) -> {kind:'ready'|'empty'|'invalid',rows,rejected,provenance}` and `parseHistoricalPrediction(payload,requestedId)`; separate parsing for model/teams/stats/reliability. `tennis-contract.js`: `parseBoard(payload,{fetchedAt,health,now}) -> {kind:'ready'|'empty'|'mock'|'invalid'|'unverified',rows,rejected,provenance}` plus `parsePrediction(payload,requestedId)`; no shared sport union with invented fields.

Every tab/resource has its own loading, ready, empty, invalid, offline, timeout, refreshing, or refresh-failed state. Good old data may remain after refresh failure, explicitly marked Last successful response and Refresh failed; never update fetchedAt on failure. Missing fields render —/Unknown, not zero. All-invalid data is Invalid response, not No predictions. A mixed board displays valid rows and explicit rejected-row count. Persist no evidence payload to localStorage.

Freshness has separate columns: browser “Fetched at” and backend-reported observation (“Logged before tipoff” NBA; “Group cache age reported by server” tennis). NBA log age is provenance, not a blanket stale rule for an immutable prediction; historical artifacts have no freshness guarantee. Tennis cache age >60 seconds is labeled Stale group cache (matches provider TTL), null/negative/nonfinite age is Unknown freshness; no per-event fresh badge. A fresh fetch does not reset cache age. Event commencement is not observedAt. Unknown feed, init, missing feed, or inconsistent health: Unverified feed, with probabilities withheld from the live board. `feed=mock` is always blocked from live presentation even with has_key=true. An explicit Show demo fixtures toggle reveals only separately labeled demo cards; demo rows never enter live counts, evidence totals, or historical record. Missing key shows provider unavailable/demo fallback and suppresses live board. Cached data can be shown as cached evidence with unknown event freshness, never an actionable view.

## Accessibility, security, and acceptance

Semantic header/nav/main, skip link, ordered headings, explicit field labels; button navigation uses aria-current, not partial ARIA tab semantics. Keyboard reaches every filter/detail/retry and focus remains stable across refreshes. Status region is polite; failures announced once. Text explains states independent of color. Touch targets at least 44px; reduced-motion support; 200% zoom and 390/768/1280 layouts. Charts have equivalent numeric tables, null-bin handling, source/cohort and lower-is-better Brier captions. Render provider names/reasons/artifact strings via textContent, never raw innerHTML.

Acceptance: all NBA tabs fully rendered without raw JSON as the only primary view; genuine empty live board is useful without fabricated games; historical lookup remains distinct; no promised market outperformance. Tennis mock/unknown feed cannot masquerade as actual live predictions; returned-ID mismatch and stale-request races fail closed. All network methods GET; no browser secrets or operational buttons. Both hash inventories unchanged before and after tests. Visual and keyboard evidence must accompany functional tests; do not call a substring page-load assertion a browser verification.
