# Runbook — 2026-27 NBA season (the single prospective claim read)

Everything in this runbook serves one pre-registered event: the Phase-2 claim
test on the 2026-27 regular season, read **exactly once** at season end
(`docs/preregistration.md` §13). Moneyline winner only, regular season only — no
playoff / play-in games, no totals. Free data only (`docs/data-cards.md`; the
T-60 injury channel is descriptive-only per its probe — no paid archive).

## The frozen arm

- `tools/season_gate.py` fits the admitted **A7** structure (feature names frozen
  after 2021-22; weights refit on the expanding window ≤ 2025-26) and seals it
  to `sports/nba/data/nba_phase2_arm_2026_27.json` with a digest. Run it ONCE,
  before the opener, and never refit during the season.
- The claim read scores only against this sealed arm. Any post-season refit is
  retrospective work, labeled like `nba_phase2_retro.json`
  (`burned_test_set: true, claim_eligible: false`).
- No claims against this season existed at registration time. That is the point.
- Ops sanity check: `python -m tools.season_ops verify` prints the sealed digest
  (expect `2bf068c9…`; a mismatch aborts the read).

## The 2026-27 schedule (the crons' input)

`leaguegamefinder` only surfaces COMPLETED games, so an upcoming season is seeded by
`sports/nba/ingest/schedule.py` (scheduleleaguev2): regular-season games with both
teams assigned, UTC tip-offs, neutral-site flags - scores stay NULL until settled.
It is idempotent (upsert), skips TBD Cup knockout placeholders (picked up on a later
run once the league assigns teams), and seeds the `seasons` FK row. Already run for
2026-27: 1,200 games (6 TBD placeholders pending).

The odds tick matches games to ESPN events through
`sports/nba/data/espn_events.json` (rebuilt weekly): 1,193/1,200 games mapped on
first build. The 7 unmapped are fixtures that moved after the schedule release;
they self-heal — the daily game-log ingest inserts games ESPN actually played
under their real ids, and the next weekly map rebuild picks them up. A tick
skips an unmapped game loudly (`no ESPN event mapped` in its output).

## Market capture (open / t60 / close)

Source: the **ESPN core API** (`sports.core.api.espn.com`) — free, key-less, and
the same provider the historical 2013-14→2025-26 corpus came from. (The Odds API
is blocked on this network — Sophos gambling-category block page, `cat=21`; see
preregistration §9, 2026-10-06.) Nothing is bought; no API key is used.

Per (game, book, side), `odds_snapshots` receives three kinds:

| kind | source field | when captured | `captured_at` |
|---|---|---|---|
| `open` | book item `.open.moneyLine` | opportunistically at any capture | NULL (provider record) |
| `t60` | book item `.moneyLine` (quoted) | only strictly before tip-off (`require_pre_tip`) | capture time |
| `close` | book item `.close.moneyLine` | post-game pass (the field populates at/after tip) | NULL (provider record) |

`tools/t60_snapshot.py` subcommands:

- `tick --schedule games.json` — one ESPN fetch per game inside [T-75, T-45]
  minutes before tip, at most once per game (`t60` dedupe); stores `t60`+`open`.
  The 20-minute cron grid always lands inside the 30-minute window.
- `postgame` — harvests `close` (+ any missed `open`) for games tipped within
  the last ~30h that have a final score.
- `map` — rebuilds the ESPN event map for the season.

In-play items (`… - Live Odds`) are excluded: an in-play price encodes the game
state. A `t60` row at/after tip-off is rejected at write time — a post-tip price
is a result.

### Pre-season rehearsal (2026-10-06, before the opener)

Two read-only probes in `scratch/`, both re-runnable:

- `t60_grid_coverage_v2.py` — the deployed `*/20 * * * *` grid covers **1,200/1,200**
  games: ≥1 tick inside [T-75, T-45] (min 1, max 2 ticks; first attempt 60-70 min
  before tip), and every in-window tick's `games_near` output contains the game.
  (v1's old `*/20 17-23,0-2` local-time grid covered 10.9%.)
- `espn_t60_rehearsal.py` — live, read-only: the opener (`0022600001`, 19:00Z Oct 20)

  serves Draft Kings odds for it, `parse_kinds` mints `t60`+`open` rows from the real
  payload, and a post-tip capture is rejected (`LatePrediction`); a completed 2025-26
  event parses `t60`+`open`+`close`.

## No live prediction log (withdrawn — §9 deviation, 2026-10-06)

The sealed A7 arm takes 10 of its 17 features (`avail_*`, `impact_*`) from each
game's own pre-game inactive list, which the free pipeline only learns from the
post-game box score. A pre-tip prediction from the sealed arm is impossible by
construction, so the daily prediction log was withdrawn (there is no `predict`
subcommand). The claim does not need it: `tools/phase2_read.py` scores the
sealed arm on settled as-of features against the live-captured market prices.

## Cron jobs (during the season)

Three **no_agent script jobs** — the scheduler runs a deterministic script, no
LLM in the loop (deliver=local, failures → telegram). Wrapper scripts live in
`~/AppData/Local/hermes/scripts/` and drive the repo's `.venv` python.

| job | schedule (local) | script | what it does |
|---|---|---|---|
| `nba-odds-tick` | `*/20 * * * *` | `nba_odds_tick.py` | emits `games.json` for games near now, captures `t60`+`open` for games in the window; silent when nothing is in the window; ≤1 fetch per game |
| `nba-daily-ops` | `30 14 * * *` | `nba_daily_ops.py` | game logs (`--force`; final scores + `results`) → box scores (played games only, inactives for features) → `season_ops refresh` (v3 feature rebuild) → `t60_snapshot postgame` (closes) |
| `nba-weekly-sync` | `0 5 * * 1` | `nba_weekly_sync.py` | schedule upsert (TBD Cup teams, moved tip-offs) + ESPN event-map rebuild |

The daily pass runs after the US slate ends (14:30 IST ≈ 09:00 UTC; the last
west-coast games end by ~07:00 UTC). The tick runs all day because tip-off times
span 16:00–04:00 UTC; the tool itself decides whether any fetch is needed.

## The 30-day capture audit (before any public output)

Audit weekly in the 30 days before anything derived from the season is published:

1. Coverage: every settled regular-season game has ≥1 `t60` row. Read the tick
   job's output for `skipped` reasons — expected: moved fixtures with no ESPN
   event yet (self-healing via the weekly sync).
2. Pre-tip discipline: zero `t60` rows with `asof_ts >= tipoff_ts` (the writer
   rejects them; a rejection is an exception — investigate any).
3. Kind coverage: `open` and `close` rows land for each game (close via the
   daily postgame pass; a missing close after 48h means ESPN never posted one).
4. Dedupe: at most one capture per (game, kind).

The audit gates go/no-go on publishing anything derived from the arm.

## Calibration window (from Task 4C)

Raw logistic ships for claims; the shipped calibration variants (A5 isotonic,
A6/A7 Platt) are diagnostics. If calibration is ever revisited, it uses the
pre-registered tune-season discipline and is re-frozen with an artifact — never
adjusted on 2026-27 results before the claim read.

## Season end (~2027-04)

Run `tools/phase2_read.py` **once** (Task 9; requires `--confirm-final`): T2′
(formula@T-60 vs opening price), T2″ (vs market at T-60 — same-information
comparison), T3 (vs closing price), on the sealed arm. It digest-verifies the
arm, refuses unsettled games, and reports T2g/T3g as "not-run, not failed".
Publish the outcome whatever it is — a published null is a first-class endpoint.
