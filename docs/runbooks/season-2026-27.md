# Runbook — 2026-27 NBA season (the single prospective claim read)

Everything in this runbook serves one pre-registered event: the Phase-2 claim
test on the 2026-27 regular season, read **exactly once** at season end
(`docs/preregistration.md` §13). Moneyline winner only, regular season only — no
playoff / play-in games, no totals. Free data only (`docs/data-cards.md`; the
T-60 injury channel is descriptive-only per its probe — no paid archive).

## The frozen arm

- `tools/season_gate.py` fits the admitted **A7** structure (feature names frozen
  after 2021-22; weights refit on the expanding window ≤ 2025-26) and seals it
  to `sports/nba/data/nba_phase2_arm_2026_27.json` with a digest. Run it ONCE,
  before the opener, and never refit during the season.
- The claim read scores only against this sealed arm. Any post-season refit is
  retrospective work, labeled like `nba_phase2_retro.json`
  (`burned_test_set: true, claim_eligible: false`).
- No claims against this season existed at registration time. That is the point.

## Cron jobs (during the season)

| job | when | tool | notes |
|---|---|---|---|
| prediction logging | T-60 before each tip | `sports/nba/live_log.py` | `log_prediction`; rows at/after tip are rejected (`require_pre_tip`) |
| T-60 odds capture | T-60 before each tip | `tools/t60_snapshot.py --schedule games.json` | `ODDS_API_KEY` from env only; stores `snapshot_kind='t60'` with `asof_ts`; nothing bought |
| daily injury report | daily | free scrape (official page) | **descriptive only** — not a claim feature (Task 6 probe) |

All three must run from a schedule of known tip-off times (`--schedule`); the
pre-tip rule is enforced at write time, not by cron timing alone.

## The 30-day prediction-log audit (before any public output)

In the 30 days before lineups / predictions are published, audit the log weekly:

1. Completeness: every scheduled regular-season game has exactly one T-60 row.
2. Pre-tip discipline: zero rows with `logged_at >= tipoff_ts` (the writer
   rejects them; a rejection is itself logged — investigate any).
3. Schema: probabilities in (0, 1), signed scores present, `surface='ml'`.
4. Odds capture: `t60` rows exist for the same games, `asof_ts` inside the
   window, `source='odds_api_h2h'`.

The audit gates go/no-go on publishing anything derived from the arm.

## Calibration window (from Task 4C)

Raw logistic ships for claims; the shipped calibration variants (A5 isotonic,
A6/A7 Platt) are diagnostics. If calibration is ever revisited, it uses the
pre-registered tune-season discipline and is re-frozen with an artifact — never
adjusted on 2026-27 results before the claim read.

## Season end (~2027-04)

Run `tools/phase2_read.py` **once** (Task 9): T2′ (formula@T-60 vs opening
price), T2″ (vs market at T-60 — same-information comparison), T3 (vs closing
price), on the sealed arm. Publish the outcome whatever it is — a published null
is a first-class endpoint. T2g/T3g report "not-run, not failed".
